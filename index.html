What is Jumpstart LocalBox?

Jumpstart LocalBox is an Azure Arc Jumpstart sandbox for learning and demonstrating Azure Local. It deploys an Azure VM that hosts a nested Azure Local environment, so you can explore the platform without procuring physical Azure Local servers. Azure Local is the infrastructure product; LocalBox is the lab environment used to explore it. “Azure LocalBox” is not the product name used in this guide. See the official LocalBox overview.

Five names, five different responsibilities
Name used in this guideWhat it means
Azure LocalThe infrastructure platform that runs the local VMs and Kubernetes workloads.
Jumpstart LocalBox; then LocalBoxThe educational sandbox. This recorded deployment has two nested Azure Local nodes inside one outer Azure VM.
LocalBox-ClientThe recorded outer Azure VM's resource name, not a separate product or an Azure Local cluster node.
Azure ArcThe Azure management capabilities connecting the local infrastructure and supported workload resources to Azure; not a general-purpose VPN.
Azure landing zonesThe enterprise organization and governance design model, not software installed by LocalBox. This guide maps a proposed target separately from the recorded lab.

Use LocalBox for training, demonstrations, and disposable proof-of-concept exercises. It runs actual Azure Local software in nested VMs, but the two nodes share the outer VM's failure domain. It is not a production deployment or proof of physical high availability. Read how the host, nodes, management services, VMs, and AKS fit together, or use the terminology and acronym reference.

Every stage expanded: execution context, identity/permissions, preflight inputs, control/data flows, operational acceptance, failure diagnosis and recovery boundaries. Recorded outcomes and honest boundaries

  • Recorded Azure Local deployment: two connected Arc nodes and completed validation/deployment.
  • Recorded AKS workload: one Linux worker plus one mandatory control plane; one NGINX replica Ready and private HTTP access.
  • Recorded VM: an Ubuntu guest on Azure Local with an identity web application and fresh cluster-owner telemetry.
  • The observed Ubuntu identity application was Python-based. Chapter 5 adds a clearly labeled new reproducible NGINX example; it is not presented as software already installed in the captured lab.
  • The migration screenshot shows the menu before destination selection. A completed manual migration and an uninterrupted application session have not been demonstrated by that image.
How to use the examples: private values are entered at runtime. Example RFC1918 IP addresses, node names, and generic resource names are instructional and must be reconciled with your own network. Commands are not an instruction to rerun an existing deployment.
